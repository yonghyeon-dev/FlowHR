# WI-0127: Employee Attendance Correction UX Upgrade

## Background and Problem

WI-0126에서 직원 셀프서비스 방향으로 복귀했지만, 출퇴근 정정은 여전히 대상 ID 수동 입력 의존이 크고
정정 전후 영향(근무시간 변화)을 즉시 확인하기 어렵습니다.
직원 여정의 핵심 KPI(90초 이내 처리)를 위해 정정 UX를 한 단계 더 단축합니다.

## Scope

### In Scope

- `/employee#attendance` 정정 UX 개선:
  - 정정 대상 기록 셀렉터 추가(최근 조회 기록 기반)
  - 선택 기록 폼 자동 반영 액션 추가
  - 정정 메모 프리셋 버튼 추가
  - 정정 요청 전 입력 가드(시간 역전/휴게 과다 등) 추가
  - 기존 대비 정정 근무시간 변화(Delta) 프리뷰 추가
- 출퇴근 기록 리스트에 대상 선택 단축 버튼 추가.
- WI-0127 회귀 테스트 추가 및 e2e suite 연결.

### Out of Scope

- 출퇴근 정책 엔진/승인 정책 변경.
- 관리자 승인 큐 자체 로직 변경.
- 모바일 전용 UI 분기 추가.

## User Scenarios

1. 직원은 최근 출퇴근 기록에서 정정 대상을 선택하고, 폼을 자동으로 채워 즉시 수정한다.
2. 직원은 정정 요청 전 근무시간 변화(기존 대비 +/-)를 확인해 실수를 줄인다.
3. 직원은 잘못된 시각/휴게 입력 시 즉시 안내를 받고 정정 요청 버튼이 비활성화된다.

## Data and API Changes

- DB 스키마 변경 없음.
- API 계약 변경 없음 (`PATCH /attendance/records/{recordId}` 재사용).
- UI/클라이언트 검증 레이어만 변경.

## Rollback Plan

- 대상 선택/프리뷰/검증 UI를 제거하고 기존 수동 입력 방식으로 되돌립니다.
- 서버 API와 데이터 모델은 변경이 없어 롤백 영향 범위가 프론트엔드에 한정됩니다.
- Recovery target: 30m.

## Definition of Done (DoD)

- [x] 직원 출퇴근 정정에 대상 선택/자동 반영/메모 프리셋이 추가된다.
- [x] 정정 요청 전에 입력 가드가 동작하고, 유효하지 않으면 요청 버튼이 비활성화된다.
- [x] 기존 대비 정정 근무시간 변화 프리뷰가 표시된다.
- [x] WI-0127 회귀 테스트가 추가되고 e2e suite에 연결된다.
